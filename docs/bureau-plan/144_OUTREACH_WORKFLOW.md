# Volume 144 — Outreach Workflow (Why Cards Exist)

## Operator journey

1. **Select target** (discovery or known HNWI / gatekeeper / issuer-linked person).
2. **Launch dig** (single-target standard depth for VIP; bulk fast for queue).
3. **Watch trajectory** (free dig is working if search/visit spans appear).
4. **Read card surface** (primary + chips + related).
5. **Validate** one route (public page still shows the number/email).
6. **Outreach** via appropriate channel (call notice-line, email IR, LinkedIn connection — **honest identity**).
7. **Log outcome** later (optional CRM — out of scope unless planned).

## Channel ethics (product constraints)

- Public sources only; no breach dumps as product data.
- No impersonation in outreach copy suggestions.
- “Validate before outreach” is permanent copy on promoted phones.
- Org routes: frame as company contact, not personal mobile.

## Why org contacts matter for rich-person outreach

HNWI personal mobiles are scarce and often privacy-scrubbed (advisors actively remove data). Public company paths remain:

- Operator → IR / main → ask for office of X,
- Notice-line → authorized agent → relationship context from filing,
- EA / chief of staff LinkedIn → professional approach.

Discarding these because they are not “direct” makes Apex **worse than a human analyst** and **worse than chat**, which happily returns HQ phones.

## Card fields that support outreach

| Field | Outreach use |
|-------|----------------|
| phone + phoneSource | Dial priority and trust |
| email + emailSource | First email draft target |
| linkedinUrl | Soft professional touch |
| contactMethod | Human-readable routing note |
| notes / llm summary | Context for first line of message |
| related people | Alternate path if primary ignores |
| companyName in metadata | Framing and EDGAR re-query |
