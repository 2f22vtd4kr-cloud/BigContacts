# Volume 280 — Dual-Brain Promote Ban (Expanded)

## Definition

**Dual-brain promote** = two controllers decide the same `entities.phone` / `email` / `linkedin` / `contactOutcome` for one person in one research window without a single ownership rule.

## Why it destroyed superiority

Live comparisons showed dig extracting public routes while cards stayed on **EDGAR-Phone** or empty. Parallel enrichers, final-review null writes, and MCTS after a successful dig are dual-brain in practice.

## Ownership rule (normative)

| Mode | Contact column owner |
|------|----------------------|
| Single-target dig | **Target contact agent / free dig** until idle |
| Discovery-only | No contact promote (candidates only) |
| After dig idle | Rehydrate from evidence (deterministic projection) |
| Issuer/registry | May fill **only if** dig/notice did not already protect the field |

## Code anchors (do not regress)

- `shouldBlockIssuerOverwrite` / `isProtectedPhoneSource` / `resolveProtectedCardPhone`
- Skip MCTS when dig already wrote routes
- `singleTargetId` forces `discoveryFirst: false`

## Planning rule

Any new “phase” that writes phone/email must declare ownership relative to dig or it is rejected in review.
