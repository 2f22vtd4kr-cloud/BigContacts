# Volume 235 — Tools Pool Industry Alignment

## External practice

- MCP and similar: one tool server, many agents bind subsets
- Progressive disclosure: don’t dump hundreds of tools into one prompt
- Provider failover inside search tool (rank fusion / multi-backend) is harness work

## Apex rules (reinforced)

1. **Small dig menu** (search, visit, browser, footprint, domain, harvest, registry, reverse_whois, done)
2. **Boss/RH tool count = 0**
3. **Discovery subset** of dig menu
4. **Observation quality > tool count**
5. New capability = new tool with clear observation schema, not a new always-on phase

## Evaluation of “more tools”

Only ship if dig agents actually select them in traces and scoreboard improves — not because a blog listed them.
