# Volume 216 — Discovery North Star

## Product question

**Who should enter the ledger next for outreach-oriented OSINT?**

Not: “Which of 150 hardcoded Google queries fires this hour?”  
Not: “Fill targetCount with any famous name.”  
Not: “Run FAA then CH then Tavily category 7 because the mixer said so.”

## North star

Discovery is an **AI-driven hunt for approachable, high-value public people** (HNWI, gatekeepers, principals, beneficial owners) where a later **free dig** can recover public contact routes.

The same failure mode that killed dig quality applies here: **scripted query playlists eliminate model judgment**. If the discovery layer only rotates templates, Apex is a random SERP scraper with a wealth theme — weaker than asking a strong LLM “who is worth researching for outreach this week in public filings and open web?”

## Success criteria

1. Admitted targets are **people** (or clearly person-linked), not shells/fame trophies only.
2. Each admitted target has a **public basis** (filing, article, registry, site) the dig can start from.
3. Mix is **useful for outreach** (reachable principals, IR-linked officers, filers) not only trophy billionaires with zero public routes.
4. Run-to-run diversity comes from **model choice + fresh signals**, not only shuffle(template_id).
5. Operator can see **why** a name was proposed (basis string, source URL).

## Non-goals

- Building a paid family-office database competitor inside Phase 1
- Exhaustive global coverage in one Atlas run
- Discovering contacts in the discovery phase (that is dig). Discovery finds **who**; dig finds **how to reach them**.
