# Volume 184 — Promote vs Present (Both Mandatory)

## Promote

Writes **entity columns**: phone, email, linkedin, phoneSource, contactOutcome, contactMethod when rules allow.

## Present

Builds **API/UI routes[]** from columns **plus** evidence-backed org/social routes that did not win the column race.

## Why both

If only promote exists, second-best IR phone vanishes when a weak personal candidate blocked it — or the reverse. Present ensures **maximum surface** on the card without lying about which value is primary.

## Rules

1. Primary = promote winner
2. routes[] includes primary + other non-trash presentable values
3. Marks required on every route
4. Identity collision → evidence only, not present primary
5. List and detail endpoints use the same present helper

## Bug class

L-UI-HIDE often means present omitted org while promote left columns empty. Fix present, not “add more dig.”
