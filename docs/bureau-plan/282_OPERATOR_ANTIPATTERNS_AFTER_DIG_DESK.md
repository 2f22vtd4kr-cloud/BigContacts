# Volume 282 — Operator Anti-Patterns After Dig-Desk

## Context

With Dig contacts, depth tiers, rehydrate, and scoreboard on the desk, operators can still burn keys and draw false conclusions. This volume lists **behavioral** anti-patterns—not code defects.

## Anti-patterns

1. **Launch discovery-first to test promote** on a known thin card. Discovery spends budget on *who*; use **Dig contacts** / `singleTargetId` for *how to reach*.
2. **Claim a win from Reactor motion** without reading ContactSurface and `phoneSource` / outcome on the card.
3. **Re-run dig in a loop** without opening DigSpan / trajectory (same failure, more spend).
4. **Enable auto-pipeline** during evaluation—runs are non-comparable and expensive.
5. **Respond to a lost COMPARE with hop lists** or “Grok parity” checklists—treats the symptom as strategy and regresses product law.
6. **Hide org / IR / notice routes** so the card “looks more personal”—violates maximum public surface and training data for operators.
7. **Ignore integrity critical** and still quote scoreboard “pass.”
8. **Confuse Boss with dig**—expecting Gemini to invent phone numbers in a plan step.

## Preferred evaluation loop

1. `healthz` → integrity not critical.  
2. Single-target dig at standard (deep if needed).  
3. Wait idle; rehydrate if evidence exists and card thin.  
4. Scoreboard snapshot.  
5. COMPARE only on systematic L-code failures.  
6. One code fix per failure class; re-cook the same ids.

## Relation to free dig

Operator discipline protects free dig: the model cannot be blamed for scripted playbooks the operator demanded after a single loss.
