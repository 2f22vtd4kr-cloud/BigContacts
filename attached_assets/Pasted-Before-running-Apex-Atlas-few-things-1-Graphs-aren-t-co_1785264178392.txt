The in-house enricher is safe — it will not overwrite web-OSINT results. It has an explicit fill-only-if-empty guard:
if (result.email && !entity.email) updates["email"] = result.email;
if (result.linkedinUrl && !entity.linkedinUrl) updates["linkedinUrl"] = result.linkedinUrl;
if (result.phone && !entity.phone) updates["phone"] = result.phone;

If web-OSINT already populated a field, in-house won't touch it.
The dangerous direction is the opposite. If you run web-osint-enrich with force=true on an entity that already has in-house data, and web-OSINT comes up empty for that entity, it will actively null those fields out:
if (result.email) updates["email"] = result.email;
else if (!entity.email) updates["email"] = null; // force=true path clears phone/linkedin too

So the safe execution order is:
1. In-house first (structured DB lookups — fast, conservative)
2. Web-OSINT second (AI pipeline — upgrades or leaves alone, never degrades)
