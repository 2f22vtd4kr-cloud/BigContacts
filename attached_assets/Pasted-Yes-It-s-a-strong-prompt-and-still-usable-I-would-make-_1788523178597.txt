Two important corrections

1. Add an explicit repository integrity rule at the top.

Because the previous session involved a risky GitHub file-edit attempt, I would add:

Before modifying anything, verify the current repository HEAD, working tree, and the full contents of any file being changed. Never perform a whole-file replacement unless the complete canonical file content has been retrieved and verified. Prefer local patch-based edits.

2. Separate “completed Dig” from “successful contact acquisition.”

A legitimate Dig can complete while finding insufficient evidence or no contact. The prompt should prevent the agent from redefining success dishonestly:

A Dig reaching canonical completion does not require finding a contact. Do not convert “no contact found” into a failure if the canonical research journey completed honestly. Completion and research disposition must remain separate concepts.
