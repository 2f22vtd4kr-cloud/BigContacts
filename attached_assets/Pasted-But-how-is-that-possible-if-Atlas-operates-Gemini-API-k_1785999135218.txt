The important difference is not whether you manually wrote the prompt. It is who controlled the research loop.
What Replit Agent did
The Replit Agent research was an interactive, open-ended investigation. It could:
1. Search the exact target name.
2. Recognize that the target was a special-purpose property company.
3. Follow the relationship to Amaron’s operating and fund-management companies.
4. Search the names of executives it discovered.
5. Open company pages, press releases, PDFs, registries, and contact pages.
6. Keep the discovered names in working context.
7. Ask a second set of searches such as:
    * "Kjell Rudsby" phone
    * "Kjell Rudsby" Amaron
    * "Amaron" contact
    * "Amaron Commercial Properties" executives
8. Return a human-readable report rather than fitting everything into Atlas’s narrow entity schema.
That is why it could produce a result like:
Kjell Rudsby — CEO / Compliance Officer — +46 (0)70 817 84 40
The prompt did not need to be manually engineered by you because Replit Agent already has hidden system-level instructions telling it how to browse, investigate, follow sources, summarize findings, and revise searches when the first result is incomplete.
In other words, Replit Agent supplied the research strategy dynamically.
What Atlas did
Atlas was executing a production pipeline, not acting as a general research assistant. Its old flow was closer to:
target company
→ fixed provider queries
→ one structured extraction prompt
→ bounded page fetches
→ JSON parsing
→ evidence attribution
→ contact adjudication
→ publication gate

That creates several failure points.
1. Atlas initially treated the SPV as the research subject
The target was:
Amaron Helsingborg Topasen 7 AB
Atlas initially concentrated on the legal entity itself. But that entity is essentially a property-holding vehicle with no useful public personnel structure.
Replit Agent made the conceptual jump:
“This is an SPV. The useful people are probably at Amaron’s operating or fund-management level.”
The old Atlas prompt did not force that jump. The later patch explicitly added the corporate-structure handoff because this was exactly the missing behavior.
2. Replit Agent was allowed to follow multi-hop relationships
Replit Agent could reason:
Topasen 7 AB
→ Amaron Real Estate AB
→ Amaron Commercial Properties AB
→ Amaron executives
→ Kjell Rudsby
→ phone number

The original Atlas pipeline was much more bounded. It could discover the parent or operator as a lead, but it did not reliably continue from:
target → operator → executive → person-specific contact

That multi-hop behavior was added only after the Amaron failure.
3. Atlas’s old schema could not properly represent the result
This is one of the strongest technical explanations.
Before the repair, Atlas had:
phone: string | null

at the organization level.
Its person-level structure supported fields such as:
name
email
linkedin
instagram
twitter

but did not have a person-specific phone field.
So if Gemini returned something like:
Kjell Rudsby — +46 (0)70 817 84 40

Atlas had no safe representation for:
phone belongs to Kjell Rudsby

It could only put the number into the corporation’s top-level phone field, which would be incorrect. A fail-closed system should reject or discard that association rather than attach it incorrectly.
Replit Agent had no such restriction. It could simply write the relationship in prose.
4. Atlas had a strict evidence gate; Replit Agent had a reporting objective
Atlas was designed to answer:
“Can this contact be safely promoted into the database as a validated route for this target?”
Replit Agent was answering:
“What can I find about this target and its relevant decision-makers?”
Those are different objectives.
Atlas required the phone to have:
* exact page-level evidence;
* a clear person-to-number association;
* correct target/entity linkage;
* acceptable source provenance;
* sufficient identity confidence;
* a valid route classification.
Replit Agent could report the number as a research finding even if the evidence was distributed across several sources.

* Replit Agent could retrieve or inspect the page more completely;

Even when you do not manually configure a prompt, Replit Agent operates under additional system instructions and has a different tool environment. It is not equivalent to sending the same text to Gemini through an API.
